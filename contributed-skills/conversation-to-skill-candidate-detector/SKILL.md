# 对话 → Skill 候选识别器

## 何时用

用户希望从一段时期内的对话里，找出"值得沉淀成 Skill"的重复话题。典型场景：定期回顾对话决定沉淀哪些工作流、AI 共学群"对话炼金"类作业。

## 步骤

1. **检索历史**：用 `conversation_search` 按时间范围检索。可并行多组角度（中文 + 英文、按任务类型）提高召回。
   - 有日期范围时带上 `start_date`/`end_date`；无历史时去掉限制确认是否真的为空。
2. **聚类与计数**：把返回的对谈按主题聚合，统计每条话题来回的轮次。只保留**跨 ≥ 5 轮**或**同类需求多次出现**的。
3. **四标准评估**：对每条候选判断是否满足（满足越多越值得做）：
   - **固定步骤**：流程清晰、有可复现的操作序列；
   - **会再次发生**：不是一次性任务，预期会再次出现；
   - **能复用多场景**：跨会话/跨项目都有用，不止这一次；
   - **目前手动重复**：现在靠人肉重复完成，自动化收益高。
4. **输出表格**：列出候选 + 轮次/频次 + 适合/不适合理由 + 建议"现在做 / 以后做"。
5. **提问确认**：明确问用户"是否要把某一条做成 Skill"，**不要擅自创建**。等用户指定后再起草 SKILL.md。

## 四标准速查

| 标准 | 满足的信号 | 不满足的信号 |
|------|-----------|-------------|
| 固定步骤 | 能写出 1-2-3 步骤 | 每次都靠临场判断 |
| 会再次发生 | 历史上已出现 ≥2 次 | 明显一次性 |
| 能复用多场景 | 换个项目也能用 | 强绑定某个私有上下文 |
| 目前手动重复 | 现在靠人反复做 | 已有工具覆盖 |

四条同时满足 → 强烈建议做；满足 2-3 条 → 可以后做；≤1 条 → 不必做（留在记忆/文档即可）。

## 输出表格模板

```
| 候选话题 | 轮次/频次 | 是否符合四标准 | 建议 |
|----------|-----------|---------------|------|
| A        | 8 轮      | 固定步骤✓ 复用✓ 手动✓ | 现在做 |
| B        | 6 轮      | 复用✓ 其余△ | 以后做 |
| C        | 5 轮      | 仅会再次发生 | 不做 |
```

## 边界与诚实

- `conversation_search` 可能返回 0 条（全新工作区、未索引、或跨账号）。此时**如实说明没有可检索历史**，不要编造话题；可改问用户口头提供近期主题。
- 评估要基于真实对话内容，不要为了凑数硬造候选。
- 最终一定以提问收尾，把"做不做、做哪个"的决定权交回用户。
