# 2026H2W5｜轻松自动化：教 Codex 学会一个低风险电脑操作流程

## 群公告

本周任务：找一个你平时会用鼠标和键盘重复完成的小流程，先判断它是否适合自动化，再让 Codex 观察你完成一遍，用一条测试数据回放验证，最后把成功流程固化成一个可复用动作。

重点不是追求“一次自动跑几十条”，而是练会四步：**判断、录制、回放、固化**。

请从低风险、可撤销、可验证的小任务开始。不要录制密码、验证码或隐私数据；不要拿自动发布、批量采集、支付、转账、删除、真实账号关键设置等场景练习。第一次回放只处理一条测试数据，涉及保存、发送、提交、上传、删除或付费时必须停下来让人确认。

完成后提交一份脱敏报告，说明你选择了什么流程、为什么适合自动化、Codex 学到了哪些步骤、第一次回放是否成功、你做了哪次人工纠正，以及这个流程以后如何安全复用。

## 任务目标

把一个“每天都要点很多遍”的电脑操作，变成边界清楚、能验证、可复用的小流程。

本周练习四个核心能力：

- 判断任务是否同时满足“有界面、没接口、路径固定、重复多次”。
- 在测试环境中示范一次，让 Codex 提炼真正的任务主线。
- 只回放一条测试数据，对比预期结果和实际结果并人工纠正。
- 把验证通过的步骤固化成带有输入、边界、停止条件和验收方法的 SOP。

## 参与者流程

1. 列出 3 个候选流程
   - 优先选择本地文件、测试文档、演示表单等低风险场景。
   - 例如：给测试文件追加固定前缀、把一条演示信息整理到测试表单、在本地应用中重复一个可撤销操作。
   - 不要使用真实客户数据、财务数据、账号后台、发布系统或支付系统。

2. 先做适用性和风险判断
   - 检查是否有界面、没有更合适的 API 或批量功能、操作路径基本固定、确实需要重复多次。
   - 同时检查是否涉及密码、验证码、个人隐私、外部发布、批量采集、支付、转账、删除或不可逆操作。
   - 有高风险项就换题，不要靠提示词硬闯。

3. 准备测试环境
   - 使用副本、测试账号、演示数据或可以随时撤销的内容。
   - 关闭密码管理器、聊天窗口、邮件和其他可能露出隐私的页面。
   - 写清预期结果和停止条件；第一次回放只允许处理一条测试数据。

4. 示范并录制一次
   - 如果 Codex 中已显示 `Record and Replay`，启动录制后亲手完成一次完整流程。
   - 流程尽量控制在 5 至 10 个主要步骤；过长时拆成多个小流程。
   - 录制结束后先让 Codex 列出它理解的步骤，不要马上回放。

5. 人工校对任务主线
   - 检查 Codex 是否识别了正确的起点、输入、关键动作、完成标志和停止条件。
   - 删除偶然动作，补充漏掉的步骤，把模糊表述改成可观察、可验证的动作。
   - 涉及保存、发送、提交、上传、删除或付费时，明确写入“执行前必须人工确认”。

6. 只回放一条测试数据
   - 指定一条与示范数据相似的测试数据。
   - 让 Codex 按校对后的流程执行；出现页面不一致、对象不确定或异常提示时立即停止。
   - 对比预期结果和实际结果，记录成功点、失败点和至少一次人工检查或纠正。

7. 固化成可复用动作
   - 给流程起一个容易记住的名字。
   - 整理一份 SOP，至少包含：适用场景、所需输入、操作步骤、禁止事项、人工确认点、异常停止条件和验收方法。
   - 如果插件不可见或系统权限暂时不可用，不要安装来源不明的替代插件；提交“候选流程评估 + SOP + 风险清单 + 环境阻塞说明”，作为基础完成。

8. 脱敏后提交打卡
   - 只提交流程说明、测试结论和复盘，不上传真实业务数据或带隐私的截图。
   - 检查报告中没有密码、密钥、邮箱、客户资料、账号、订单号、本机绝对路径等敏感信息。

## 可复制提示词

筛选适合录制回放的任务：

```text
我想把一个重复电脑操作教给 Codex。下面是我的 3 个候选流程：

1. [候选流程一]
2. [候选流程二]
3. [候选流程三]

请先只做评估，不要操作电脑。

对每个候选流程检查：
1. 是否有界面。
2. 是否没有更合适的 API、批量导入导出或现成自动化。
3. 操作路径是否基本固定。
4. 是否需要重复多次。
5. 是否涉及密码、验证码、隐私、外部发布、批量采集、支付、转账、删除或不可逆操作。

请用表格给出“适合 / 不适合 / 需降风险后再试”的结论、理由和降风险办法，最后只推荐一个最适合用测试数据练习的流程。
```

录制前生成安全清单：

```text
我要录制这个测试流程：[流程名称]。

请先生成一份录制前安全清单，不要开始操作电脑。清单必须包括：
1. 使用什么副本、测试账号或演示数据。
2. 录制前要关闭哪些可能暴露隐私的窗口。
3. 本次只允许处理哪一条测试数据。
4. 哪些动作前必须人工确认。
5. 出现哪些情况必须立即停止。
6. 完成后如何验证结果。

如果这个流程不适合录制回放，请直接说明原因并建议换题。
```

录制后校对任务主线：

```text
我已经完成一次示范录制。请先停止并总结你理解的流程，不要回放。

请按下面结构输出：
1. 流程名称。
2. 起点和所需输入。
3. 5 至 10 个主要步骤。
4. 完成标志。
5. 必须人工确认的动作。
6. 异常停止条件。
7. 你不确定或可能漏掉的步骤。

请把偶然的鼠标移动和无关动作排除，只保留完成任务所需的主线。等待我校对后再执行。
```

只回放一条测试数据：

```text
请按我刚才确认的流程，只处理这一条测试数据：[测试数据说明]。

边界：
1. 不处理第二条数据。
2. 不输入密码或验证码。
3. 不访问未明确指定的页面、文件或账号。
4. 遇到页面不一致、对象不确定、异常提示或权限请求时立即停止并告诉我。
5. 在保存、发送、提交、上传、删除、发布或付费前停下，等待我确认。
6. 完成后说明实际执行步骤和验证结果，不要继续下一条。
```

固化成可复用 SOP：

```text
请把刚才验证过的流程整理成一份可复用 SOP。

必须包含：
1. 流程名称和一句话用途。
2. 适用场景与不适用场景。
3. 所需输入和开始条件。
4. 编号操作步骤。
5. 禁止事项和人工确认点。
6. 异常停止条件。
7. 完成后的验收方法。
8. 一条以后可以直接调用这个流程的提示词。

不要把密码、账号、客户信息、真实文件路径或测试数据写进 SOP。
```

## 完成标准

只要提交内容能证明下面这些点，就算完成：

- 评估了 3 个候选流程，并按“有界面、没接口、路径固定、重复多次”选出一个低风险任务。
- 使用副本、测试账号、演示数据或可撤销内容，没有直接操作唯一原件或真实关键系统。
- 录制后先人工校对 Codex 理解的任务主线，没有直接批量回放。
- 第一次回放最多处理一条测试数据，并对比了预期结果和实际结果。
- 记录了至少一次人工检查或纠正。
- SOP 包含输入、步骤、禁止事项、人工确认点、异常停止条件和验收方法。
- 没有录制或提交密码、验证码、隐私数据，也没有用于自动发布、批量采集、支付、转账、删除等高风险场景。
- 作业报告已脱敏，只提交过程、判断和经验。

如果 `Record and Replay` 不可见或系统权限暂时不可用，完成候选流程评估、可复用 SOP、风险清单和环境阻塞说明，也可作为基础完成；不要为了交作业安装来源不明的插件或绕过系统安全限制。

## 带班复盘

审核打卡时，重点看三件事：

- 好的提交：选题低风险、第一次只跑一条、步骤可验证、失败会停止、关键动作保留人工确认。
- 需要改进：一上来就批量执行、把录制等同于理解、没有测试环境、没有异常停止条件、上传带隐私的截图。
- 最适合群里讨论的问题：Codex 在第一次回放中误解了哪一步，你是怎样发现并纠正的？

周复盘可以统计：

1. 大家最常选择的重复操作类型。
2. 最常见的录制遗漏或回放失败原因。
3. 最值得沉淀成个人技能的低风险流程。
