# 2026H2W12｜把客户档案流程封装为 Skill，用客户 B 验证复用

任务周期：2026-09-21 至 2026-09-27。

本周是独立作业、独立打卡与统计。W11 练“把客户档案做准”，W12 练“把方法封装后换客户复用”；不与 W11 或 W9/W10 课程导入合并计数。

## 群公告

本周把上周做客户档案的方法整理成一个可复用 Skill，再开新会话，用客户 B 验证。重点不是生成一个 SKILL.md 就算完成，而是检查它有没有真正被使用、能否生成三份成果、有没有编造或残留客户 A 的信息。本人回读至少三条关键结论，其中至少一条涉及冲突。

新同学先安装、老同学更新 ai-colearning-weekly-task-publisher；使用 Codex、WorkBuddy 或 DSH 领取任务。客户档案 Skill 是本周自己制作的产物，不需要预先安装同名专用 Skill，也不要求额外购买课程或得到大脑会员。工具自身账户与使用额度由各自环境决定。往周主题在 references/weeks，打卡交流在仓库 Issues。

## 任务目标与产出

本地保留：

- 客户档案 Skill 的 SKILL.md（必要时带你自己编写的通用模板）。
- 客户 B 的客户全景档案.md、冲突与待确认.md、核验记录.md。
- 新会话测试记录：初次结果、问题、规则修订、复测结果；没有发现问题时写实际通过依据，不编造修改。

公共 PR 只提交一份脱敏过程报告：references/submissions/2026H2W12-昵称.md。报告摘要说明 Skill 的结构与关键规则、测试及本人核验过程；Skill 和完整成果留本地，不附原始材料、真实客户信息或单位名称。

## 参与者操作步骤

### 1. 准备材料与上周规则

- [W11 正式任务](2026H2W11.md)。
- [客户 A 材料](../materials/2026H2W11/客户A/)：仅用于提炼和修正方法。
- [客户 B 材料](../materials/2026H2W11/客户B/)：留给新会话测试。
- 两套材料均为聊天记录、邮件、合同草案、客户表四类公开虚构输入。文件仍放在 W11 材料目录，不代表 W12 归入 W11。

已做 W11 的同学先修正已发现的问题；未做过的新同学先用 A 做一次最小练习并本人核对，不必补交 W11 才能参加 W12，也不要声称此前已经完成。

### 2. 把方法写入 Skill

请让所用工具按其实际支持的格式创建一个客户档案 Skill，至少写清：

- 名称、用途、明确的触发场景与不适用场景。
- 输入四类材料，缺文件或文件不可读时如何说明缺口。
- 先列来源，再提取事实、识别冲突和未知，最后生成建议。
- 三份输出的结构；金额、日期、状态、承诺等关键结论标到文件及条款、记录日期或表格字段。
- 冲突保留各方原值，不凭来源类型、数量或日期新旧自动裁定。
- 未说明不等于已完成，也不等于确定未发生；新增人工信息须单列来源，不冒充原件事实。
- AI 自查与本人核验分开。人工核验栏先留待填写，不能代写已验收。
- 输入只读，输出写独立目录；不联系客户、不发送消息、不修改源文件。

只保留方法，不能把 A 的名字、编号、价格、账号数、日期或具体结论写成默认值。不要求脚本、联网服务或复杂技能体系。

### 3. 在工具中加载，并开新会话测试 B

请工具说明当前环境支持的安装或加载方式，再实际验证。不同工具路径不同，不照抄一个所谓通用安装路径。

新会话使用独立测试目录，只提供 Skill、客户 B 的四份输入与简短任务，不传 A 的档案、旧对话或参考答案。新会话不一定清除项目全局规则，须检查是否有 A 的材料或旧规则被自动带入。

先用自然任务描述测试能否识别并使用 Skill；若未自动触发，再显式调用或要求读取 SKILL.md，记录实际方式。仅手动粘贴规则只能称规则执行验证，不能冒称原生 Skill 安装及自动触发成功。

记录是否实际读取/加载了 Skill、是否生成三份可读文件、是否每个关键结论有来源。不能仅凭 AI 说“已使用”认定生效。

### 4. 本人回读三条，检查是否可复用

本人打开 B 原件，至少核对三条关键结论，含至少一项冲突。每条记录：输出原结论、来源位置、本人判断、修改或通过依据。

核验的是“输出是否忠实于资料”，不是要求你替虚构客户裁定业务事实。材料不足就保留冲突，不为完成作业虚构签署、价格、付款或培训确认。

另查：是否混入 A 的名称、编号、数值、日期或产品。相同数值本身不一定是残留，关键看能否在 B 原件找到依据。

### 5. 修改通用规则并复测

发现问题时修改 Skill，而不是把客户 B 的答案写进去。保留初测与修订记录，再开新会话用 B 复测，记录哪些问题消失、哪些仍在。没有问题时记录核验依据即可，不强制编造一轮修改。

B 已经被用于调试后的复测不再是首次测试；通过 B 也不代表已经适用于所有客户。遇到环境或加载阻塞，写清已完成、未执行与下一步，不冒称完整通过。

## 完成标准与复盘

- 本地 Skill 可读，规则通用且有明确触发与输入输出约定。
- 实际完成新会话 B 测试，记录加载方式与三份产物，不能把写出 Skill 当成复用通过。
- 本人核对至少三条关键结论（含冲突），能回到原件；AI 自查不能替代。
- 关键结论有来源、冲突并列、未知不编造，无无来源的客户 A 残留。
- 发现问题时修订规则并记录复测；未执行和真实阻塞明确标出。
- 学习打卡与完整验收分开，不把未通过的测试写成成功。

复盘：哪条规则真正帮到了 B？新会话暴露了什么旧上下文依赖？还有哪些客户类型或异常输入没有测试？
