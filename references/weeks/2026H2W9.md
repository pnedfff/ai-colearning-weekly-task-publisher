# 2026H2W9｜把一门得到课程接入得到大脑：练一次 Skill 串联工作流

## 群公告

这周不练一条孤立提示词，而是把几个能力串成一条真实工作流：**你已授权的得到课程 → 浏览器发现全部已发布正文链接 → 本地清单去重 → 得到大脑（GetNote）提取全文 → 异步状态核验**。

新同学先安装 [AI 共学群周任务发布器](https://github.com/pnedfff/ai-colearning-weekly-task-publisher)；新老同学都要安装或更新本周专用的 [dedao-course-to-getnote](https://github.com/pnedfff/dedao-course-to-getnote)，再从自己已登录的得到课程文章开始。每个人只处理自己已购买或本来有权访问的课程；不为交作业购买课程、不绕过登录或付费墙，也不在群里或 GitHub 上传课程全文、链接清单、Cookie、密钥或账号截图。

## 任务目标

完成后，你应能看懂一个可复用的 Skill 串联工作流中各步骤的输入、输出与边界：

- 浏览器只从当前登录态发现课程自身、已发布的正文 URL；
- 本地清单按文章 ID / URL 去重，先做预检；
- 得到大脑接收 URL 并自行提取全文，重复内容不重复保存；
- 以最终同步状态而不是“命令跑完了”判断是否完成。

本周的学习重点是**工作流编排和核验**，不是把课程内容复制出来。

## 参与者流程

1. 准备自己的授权环境
   - 新同学先安装 `ai-colearning-weekly-task-publisher`；新老同学都安装或更新 `dedao-course-to-getnote`。
   - 所有人确认自己的浏览器已登录得到、`getnote auth status` 已授权；没有权限或课程未购买就停在这里，不绕过。

2. 打开一篇你有权阅读的得到课程正文
   - 在当前已登录浏览器里打开课程内任意一篇已发布文章。
   - 让 Skill 回到课程目录，收集该课程所有**已发布正文**的标题、顺序和规范 URL；未发布讲次只记录数量，不伪造 URL。

3. 先预检，不直接写入得到大脑
   - 生成本地 `course-articles.json` 清单，按文章 ID 和 URL 去重。
   - 运行预检，得到“已发布 / 已存在 / 待新增”三个数字；清单和状态文件只留在本机，不提交 GitHub。

4. 确认后再同步并核验
   - 只把预检后的、你有权访问的 URL 提交给自己的得到大脑。
   - 等待异步任务完成，记录新增、重复、失败和未发布数量；失败项按 Skill 的断点续传规则处理，不盲目重复提交。

5. 写一份脱敏工作流报告
   - 公共作业只说明数量、步骤、真实阻塞和一条可复用经验。
   - 不粘贴课程正文、完整 URL 清单、浏览器网络响应、Cookie、账号、密钥或得到大脑笔记全文。

## 可复制提示词

先建立清单并预检：

```text
请使用 dedao-course-to-getnote Skill，处理我当前浏览器中已登录、且我有权访问的一门得到课程。

请从当前打开的课程文章回到课程目录，只收集这门课程所有已发布正文的安全字段和规范 URL；不要导出 Cookie、请求头、签名、完整响应或课程正文。

先把清单保存到本机 course-articles.json，并执行 dry-run 查重。此阶段不要向得到大脑新增内容。

请告诉我：课程规划总数、当前已发布数、已存在数、待新增数、未发布数；抽查首篇、中段、末篇是否都是正确正文。不要在对话中输出完整 URL 清单或全文。
```

确认预检后再同步：

```text
我确认同步刚才预检得到的清单。请只将我有权访问、且未重复的得到课程正文 URL 提交到我的得到大脑（GetNote）提取全文。

保持最多 3 条并发，保留同步状态文件并等待异步结果。完成后只汇总新增数、重复数、失败标题、未发布数和可恢复的下一步；不要把课程全文、链接清单、Cookie、密钥或账号信息输出或写入公共仓库。
```

只提交上面的脱敏打卡报告；不要提交课程全文、完整 URL 清单、Cookie、账号截图、密钥、GetNote 同步状态文件或本机绝对路径。提交前逐项检查敏感信息，再创建 PR。

## 完成标准

- 使用本人有权访问的课程，或如实记录登录、购买、授权等真实阻塞；不绕过任何访问控制。
- 清楚说明浏览器、清单、预检、得到大脑同步和状态核验如何衔接，而非只贴一段提示词。
- 标准完成应报告已发布、重复、待新增 / 新增、失败和未发布的真实数量；不能把计划讲次当作已同步内容。
- 公共 PR 仅含自写、脱敏的工作流报告，不含课程正文、完整链接清单、凭据或账号信息。

## 带班复盘

- 最容易混淆的边界：浏览器发现 URL、得到大脑提取全文、公共作业报告，三者分别该保存什么？
- 值得展示的案例：哪位同学把“先预检、再同步、再核验”的状态链讲得最清楚？
- 下一周要延续的一条规则：先让上一步产出可检查的输入，再允许下一步写入。
