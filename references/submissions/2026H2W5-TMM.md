# 2026H2W5 打卡：把重复的学习记录录入流程做成 Skill

提交人：TMM
GitHub 账号：tmm266

本次最终产出不只是一份 SOP，而是一个可由 Codex 触发的 `record-learning-log` Skill。Skill 把“检查测试环境——录入一条记录——逐格验证——保存前人工确认”固化为可重复执行的流程。

## 1. 我评估的 3 个候选流程

1. 在测试表格中录入一条虚构的学习记录。
2. 给副本文件添加固定前缀。
3. 把一条演示信息按固定模板整理到测试文档。

| 候选流程 | 结论 | 理由 |
| --- | --- | --- |
| 录入一条学习记录 | 适合 | 有固定表格界面、字段和路径，单条结果容易验证，使用虚构数据时风险低。 |
| 批量添加文件前缀 | 不优先 | 访达已有批量重命名功能，且操作错误会影响多个文件。 |
| 整理演示信息到测试文档 | 需降风险后再试 | 界面操作固定，但文本整理带有语义判断，验收标准不如表格字段清晰。 |

## 2. 我最终选择的流程

在 Excel 空白测试工作簿中，录入一条虚构学习记录。

测试字段为：日期、学习主题、用时、收获、下一步。测试内容全部为虚构学习记录，不包含真实业务或个人隐私数据。

## 3. 它为什么符合“有界面、没接口、路径固定、重复多次”

- 有界面：操作对象是 Excel 工作表。
- 没有必要接口：少量日常学习记录不值得单独开发 API 或导入流程。
- 路径固定：每次都是定位第一个空行，再依次填写 5 个固定字段。
- 重复多次：学习后可反复记录，每次的操作结构相同。

## 4. 我如何准备测试环境和安全副本

- 从 Excel 的“空白工作簿”模板新建独立工作簿，不打开任何最近使用的真实文件。
- 只准备一条虚构数据，不允许处理第二条。
- 不使用账号、邮箱、客户、订单、财务或联系方式等真实数据。
- 将“界面焦点不在预期单元格、输入字段丢失、出现权限提示”设为异常停止条件。
- 保存前必须先检查 5 个字段是否全部进入正确列。

## 5. Codex 从示范中提炼出的主要步骤

1. 打开 Excel，选择空白工作簿。
2. 确认当前工作簿为新建空白文件。
3. 从 A1 开始建立表头：日期、学习主题、用时、收获、下一步。
4. 定位到 A2，只录入一条虚构学习记录。
5. 通过 Tab 键按顺序进入下一列。
6. 录入后逐列检查字段位置和内容。
7. 在保存前暂停，确认验收结果。
8. 若发现焦点漂移、字段丢失或权限错误，立即停止，不继续输入第二条。

## 6. 我校对或补充了什么

我补充了两个关键检查：

1. 不能只看光标最后停在哪里，必须用截图或逐格检查确认实际写入结果。
2. 中文输入可能受焦点和输入法状态影响，不能将“已执行输入动作”当成“数据已正确写入”。

## 7. 第一次单条回放的结果

结果：**部分成功，未通过验收。**

- 成功点：创建了独立空白工作簿，没有打开或修改现有文件；日期和用时等部分数据被写入测试行。
- 失败点：一次性输入表头和记录时，字段没有按预期形成 5 列；中文字段出现丢失，使用区域和焦点也出现偏移。
- 验收结论：由于 5 个字段没有全部准确进入对应列，本次不能标记为回放成功。

## 8. 我做的一次人工检查或纠正

我先通过工作表截图核对实际结果，发现只有部分字段可见，与预期的 5 列结构不一致。

纠正时尝试改为逐字段输入，但中文内容仍受焦点漂移影响。随后 Excel 的电脑控制授权被撤回，因此我按预设停止条件结束测试，没有继续批量试错，也没有处理第二条数据。

## 9. 人工确认点和异常停止条件

### 人工确认点

- 打开后确认是独立空白测试工作簿。
- 录入后确认 5 个字段分别位于正确列。
- 保存前确认没有真实业务数据或隐私信息。
- 执行保存动作前暂停，由人确认。

### 异常停止条件

- 当前文件不是新建空白工作簿。
- 单元格焦点不在预期位置。
- 中文输入丢失、偏移或进入错误列。
- 出现恢复现有工作簿、账号、权限或其他未预期弹窗。
- 应用撤回电脑控制授权。
- 完成一条后立即停止，不自动处理第二条。

## 10. 流程名称和以后的调用提示词

## 12. 可复用 SOP

### 适用场景

- 向专用测试表格录入一条非敏感学习记录。
- 表头和列顺序固定，结果可以逐格验证。

### 不适用场景

- 真实客户、财务、订单、联系方式或其他隐私数据。
- 一次批量录入多条数据。
- 保存位置、工作表结构或字段位置不确定的文件。

### 所需输入和开始条件

- 一个独立空白测试工作簿。
- 一条虚构学习记录。
- 固定表头：日期、学习主题、用时、收获、下一步。
- 电脑控制权限正常，且未打开真实工作簿。

### 操作步骤

1. 启动 Excel 并选择空白工作簿。
2. 检查窗口标题和工作表状态，确认没有打开现有文件。
3. 在 A1:E1 设置固定表头。
4. 定位到 A2，逐字段输入一条测试记录。
5. 每次移动到下一列后，检查名称框中的单元格坐标。
6. 录入完成后，用截图和逐格检查核对五个字段。
7. 发现任何错列、缺失或焦点漂移时立即停止，只记录差异，不继续下一条。
8. 验证全部通过后，在保存前等待人工确认。

### 禁止事项

- 不打开或改动任何最近使用的现有工作簿。
- 不输入密码、验证码、账号或真实业务数据。
- 不在第一条验收通过前处理第二条。
- 不在未经人工确认时保存、覆盖或上传文件。

### 验收方法

1. A1:E1 的表头顺序正确。
2. A2:E2 只有一条测试记录。
3. 5 个值均与测试输入一致，不缺失、不错列。
4. 没有第二条数据，没有真实业务或隐私信息。
5. 保存前已经人工确认。

## 13. 我做成的 Skill

### Skill 名称

`record-learning-log`

### 触发场景

当用户说“把这条学习记录录入测试表格”、“记录一条学习日志”或“测试录入一条学习数据”时触发。

### Skill 包含的重复操作

1. 检查当前文件是空白工作簿或指定测试副本。
2. 只录入一条非敏感学习记录，并在每次移动后检查单元格焦点。
3. 逐格读回五个字段，对比预期值与实际值。
4. 保存前暂停等待人工确认，不自动处理第二条。

### `SKILL.md`

```markdown
---
name: record-learning-log
description: Safely enter exactly one non-sensitive learning record into a test spreadsheet and verify every field before saving. Use when the user asks to record, add, log, or test-entry a learning note in Excel or another spreadsheet through a repeatable computer-interface workflow.
---

# Record Learning Log

Safely add one learning record to a dedicated test spreadsheet. Keep the workflow bounded, reversible, and observable.

## Required inputs

Collect or confirm these five fields before operating the interface:

1. Date
2. Learning topic
3. Time spent
4. Main takeaway
5. Next action

Use fictional or explicitly non-sensitive data for tests. Never infer missing values that would materially change the record.

## Workflow

1. Inspect the target
   - Confirm the active file is a new blank workbook or a user-designated test copy.
   - Do not open recent workbooks or unrelated files.
   - Confirm the expected columns are `Date`, `Learning topic`, `Time spent`, `Main takeaway`, and `Next action`.

2. Set the boundary
   - Process exactly one record.
   - Do not enter passwords, verification codes, account details, customer information, financial data, or private contact information.
   - Stop if the workbook, sheet, starting cell, or column order is uncertain.

3. Enter the record
   - Locate the first empty row beneath the header.
   - Enter one field at a time in the fixed column order.
   - Re-check the active cell after every move to the next column.
   - Do not use bulk paste when the input method or focus behavior is unverified.

4. Verify the result
   - Read back all five cells from the completed row.
   - Compare each actual value with the requested value.
   - Treat missing text, wrong columns, focus drift, unexpected dialogs, or permission changes as a failed run.
   - If verification fails, stop and report the mismatch. Do not process another record.

5. Save only after confirmation
   - Summarize the target workbook, completed row, five verified values, and any warnings.
   - Pause before saving, uploading, sharing, or overwriting.
   - Save only after the user confirms the exact destination.

## Stop conditions

Stop immediately when any of these occurs:

- The active workbook is not the expected blank workbook or test copy.
- A value lands in the wrong cell or disappears.
- The interface focus moves unexpectedly.
- A recovery, account, permission, upload, or sharing prompt appears.
- Computer-control permission is unavailable or revoked.
- One test record has already been attempted.

## Completion report

Report:

- Target type: blank workbook or test copy
- Attempted row and fields
- Verification result for each field
- Human correction, if any
- Save status
- Any stop condition or environment blocker

Never claim success unless all five values were read back from the expected cells.
```

## 14. Skill 验证和试运行

### 测试提示

> 使用 `$record-learning-log` 将这条虚构学习记录录入空白测试表格：日期 2026-08-09，学习主题“高情商沟通力”，用时 30 分钟，收获“先共情再建议”，下一步“练习一次复述确认”。只处理一条，保存前等待我确认。

### 试运行结果

- Skill 正确选择了空白工作簿，没有打开现有文件。
- 第一次输入只处理了一条测试数据。
- 验证时发现中文字段丢失和单元格焦点漂移，不符合五列验收标准。
- 人工纠正仍未稳定，随后电脑控制权限被撤回。
- Skill 按停止条件结束执行，没有保存错误结果，也没有处理第二条。

结论：**界面回放未成功，但 Skill 的边界、验证和停止机制按预期生效。**
