## 1. 我选的文件夹和理由

- **文件夹**：`homework_w4/`（本项目下的练习目录）
- **理由**：承接 W3 数据核查的真实经验。W3 中 AI 把"待人工补录"误填进客户等级字段，暴露了"标记和数据层混淆"的问题；W4 正好把这条教训沉淀成项目宪法，避免下次再犯。

## 2. 我的 AGENTS.md 包含哪些规则（共 9 块）

| # | 规则块        | 解决的问题                         |
| - | ---------- | ----------------------------- |
| 1 | 角色与边界      | 明确 AI 是助手不是决策者；不确定先问          |
| 2 | 文件分级       | 区分只读（原始数据）、可写（日志）、工作副本（\_修复版） |
| 3 | 数据核查 5 步流程 | 防止跳步（W3 教训：必须先只读扫描再修复）        |
| 4 | 默认业务口径     | W3 学到的：金额 2 位小数、负数量剔除、缺失值保留空  |
| 5 | 敏感信息红线     | 提交 PR 前必查清单（邮箱、客户名、绝对路径）      |
| 6 | 输出格式约定     | 文件名 / PR 标题 / 报告开头三件套         |
| 7 | 失败模式记录     | 来自 W3 的 3 条真实教训               |
| 8 | 何时停下来问我    | 金额差 > 1 元、缺失 > 3 行等触发条件       |
| 9 | 维护方式       | 改动留痕，不塞临时素材                   |

## 3. 我使用 AGENTS.md 的方式

把 `AGENTS.md` 放在目标文件夹根目录。Codex 进入该目录时优先读取本文件，按规则操作，不再每次重新问"单价保留几位小数""缺失值怎么处理"这类口径问题。

测试方式：让 Codex 重新跑一次 W3 的数据核查流程，观察它是否：

- 不再写"待人工补录"到数据字段 ✅
- 不再跳过只读扫描直接修复 ✅
- 不再臆造客户等级 ✅

## 4. 我从 W3 沉淀的 3 条规则

1. **标记属于日志层，不属于数据层**。"待人工补录"是日志提示，不是字段值。
2. **AI 候选修复版必须人工抽查 3 点以上**才能交付。看起来完整 ≠ 实际正确。
3. **默认口径必须写入 AGENTS.md**，否则每次都要重新问。比如"金额统一 2 位小数"。

## 5. 我学到的 1 条经验

**"规则前置"比"事后纠正"便宜 10 倍**。  
W3 我花了一轮人工抽查才纠正 AI 把"待人工补录"写错地方的问题；W4 把规则写进 AGENTS.md 之后，Codex 第一轮就按规则操作，省掉了 1 轮返工。
