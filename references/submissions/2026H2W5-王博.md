## 1. 我评估的 3 个候选流程

- **候选一（最终选择）**：在 WorkBuddy 里把一段长对话提炼成可复用技能（skill），并在真正落盘前向我确认是否要生成 skill 文件。
- **候选二**：把每周重复的"整理会议纪要"用脚本自动化 —— 但涉及真实会议记录与参会人信息，隐私风险偏高，需先脱敏再试，本次不采用。
- **候选三**：批量重命名下载文件夹里的文件 —— 系统已有现成的批量重命名功能/接口，不符合"没接口"原则，放弃。

## 2. 我最终选择的流程

**提取长对话并询问是否做成 skill**：在 WorkBuddy 中，把一段较长的对话提炼为结构化的技能定义，并在正式生成文件前向我确认。

## 3. 它为什么符合"有界面、没接口、路径固定、重复多次"

- **有界面**：完全在 WorkBuddy 的对话 / 技能界面里操作，不碰后台、不碰系统设置。
- **没接口**：没有现成的"对话 → skill"一键 API，需要 AI 理解对话内容后按规则生成。
- **路径固定**：每次都是 `读取对话 → 提炼要点 → 判断可否做成 skill → 询问确认 →（同意则）生成 skill`，步骤稳定。
- **重复多次**：每当一个长会话沉淀出可复用经验，就要重复做一次，手动做很费时。

## 4. 我如何准备测试环境和安全副本

- 用一段我自己编写的**示例长对话**（非真实客户 / 业务数据）作为测试输入。
- 关闭了可能含隐私的其他窗口；不读取任何含密码、验证码、客户资料的真实会话。
- 明确预期结果：技能应只提炼出"流程骨架 + 触发场景 + 边界与禁止项"，**不擅自写文件**。

## 5. Codex 从示范中提炼出的主要步骤

（即技能固化后的执行主线）

1. 读取目标长对话，识别其中的"可复用操作 / 结论 / 用户偏好"。
2. 提炼为技能骨架：名称、触发场景、输入、步骤、边界与禁止项。
3. 判断该内容是否适合做成 skill（是否有重复价值、是否含敏感信息）。
4. 向我提问："要不要把这段做成 skill？" 并给出建议。
5. 若我同意，再生成 skill 文件；若不同意，仅输出提炼结果。

## 6. 我校对或补充了什么

- 补充了"涉及敏感信息时不建议做成 skill"的边界规则。
- 把"自动落盘生成文件"改为"**先询问确认再生成**"，避免误写。
- 要求输出必须脱敏，不得夹带对话里的真实人名 / 账号 / 本机路径。
