# 2026H2W1 打卡报告：用 Codex 安全整理一个混乱文件夹

## 一、任务说明

我选择了一个包含课程视频、表格、图片、PDF 和 Word 文档的混合资料文件夹进行练习。为了避免公开本机信息和个人资料，本报告不包含本机绝对路径、真实个人文件名、课程作者姓名或文档正文。

本次实际完成了以下阶段：

1. 创建项目规则文件，明确只操作当前项目文件夹、第一轮只读、禁止删除和覆盖、不确定时先确认。
2. 递归只读盘点文件类型、数量、大小、目录结构和 SHA-256 哈希。
3. 识别疑似重复、版本命名异常和用途不明文件。
4. 在不修改原文件的前提下提出分类结构、放置规则、命名规则和待确认处理方案。
5. 在等待确认期间停止，没有提前移动、重命名或删除文件。

本次尚未执行批量整理和二次调整，因此下面记录的是已完成的规则创建、只读盘点和整理方案，不把计划中的操作写成已经完成。

## 二、安全边界

项目规则包括：

- 默认使用中文沟通。
- 只允许操作当前项目文件夹。
- 第一轮只读盘点，不移动、不重命名、不修改、不删除文件。
- 禁止删除任何文件，禁止覆盖已有文件。
- 无法判断的文件加入待确认清单，不强行分类。
- 需要确认的操作先询问。
- 执行后更新整理日志。

盘点期间只读取文件路径、扩展名、大小、修改时间和内容哈希，没有打开文档正文，也没有播放视频。所有“可能用途”均由脱敏后的文件名和目录关系推断。

## 四、重复文件和版本风险

| 检查项 | 结果 | 处理判断 |
|---|---|---|
| SHA-256 完全重复 | 121 个文件中未发现内容完全相同的文件 | 不进行重复删除 |
| 同主题表格与图片 | 文件名主题相同，但格式和哈希不同 | 可能是源文件与导出图，作为关联文件保留 |
| 两个日期相同的训练视频 | 名称相近，但大小和哈希不同 | 无法判断是否为不同训练或不同版本，加入待确认 |
| 跨课程相似主题 | 多套课程都有声音、眼神、选题和文案内容 | 来源不同，保持课程包完整，不跨课程去重 |
| 重复扩展名 | 发现 50 个 `.mp4.mp4` 文件 | 更像命名问题，不代表内容冲突 |
| 转码痕迹命名 | 发现 3 个 `.mov.mp4` 文件 | 可能是 MOV 转码后的 MP4，先不改名 |
| 统一导出后缀 | 一组 36 个视频全部带相同导出后缀 | 视为同一批次标记，不认定为版本冲突 |
| 课程编号 | 四组编号课程均连续，无重复前导编号 | 未发现明显缺课或编号冲突 |

没有发现带“旧版、最新版、最终版、final、copy、副本”等明显版本标记的文件。修改时间只能作为线索，不能单独用于判断新旧版本。

## 五、待确认事项

| 问题 | 推荐处理 |
|---|---|
| 五套课程是否必须保持原课程包完整 | 保持完整，只整理外层目录 |
| 根目录资料按主题还是按文件类型分类 | 按主题分类，查找更直观 |
| 个人健康方案是否需要单独隔离 | 放入个人资料区域 |
| 职场提示词归入 AI 资料还是职场资料 | 暂归 AI 与提示词，等待确认 |
| 同主题表格和图片是否为配套关系 | 放在同一主题目录，不视为重复 |
| 两个日期相同的视频是否为不同课程或版本 | 确认前保留原位 |
| 是否统一修正重复扩展名 | 先生成改名映射表，确认后再改 |
| 原课程总目录的数字前缀是否保留 | 确认其是否代表原有分类编号 |

## 六、整理方案

建议按主题分类，同时保持课程包内部结构完整：

```text
资料整理副本/
|-- AGENTS.md
|-- 整理日志.md
|-- 01_课程资料/
|   `-- 镜头表现力/
|       |-- 01_课程包A_6节/
|       |-- 02_课程包B_36节/
|       |-- 03_课程包C_34节/
|       |-- 04_课程包D_25节/
|       `-- 05_赠送训练/
|-- 02_知识资料/
|-- 03_教育学习/
|-- 04_个人资料/
|-- 05_表达与内容创作/
|-- 06_AI与提示词/
|-- 90_待确认/
`-- 99_项目说明/
```

文件放置规则：

- 规则文件和整理日志保留在根目录，便于随时检查。
- 课程视频按来源成套保存，不把相似主题拆散或跨课程合并。
- 同一主题的源文件与导出件放在同一目录。
- 涉及个人健康信息的资料与公开课程分开保存。
- 无法确定用途、版本或归属的文件，在确认前保留原位。
- 不删除文件；即使确认重复，也只登记并等待用户另行决定。

命名规则：

- 目录使用 `两位序号_主题_补充说明`。
- 课程视频使用 `三位课序_课程标题.mp4`。
- 普通资料使用 `主题_用途_YYYYMMDD_v01.ext`。
- 不使用“最终版”“最新版”等会随时间失效的名称。
- 所有改名先生成“原路径 -> 建议新路径”映射表，确认后执行。
- 修正重复扩展名只改变文件名，不进行转码，也不改变文件内容。

待确认文件处理流程：

1. 登记原相对路径、大小、哈希、疑点和建议归属。
2. 未确认前保留原位，不擅自移动到新目录。
3. 确认是独立资料后再归类；确认是版本关系后使用 `v01`、`v02`。
4. 即使确认重复，也不删除，只标记状态。
5. 执行前生成完整操作预览，执行后复核文件数量和哈希。

计划生成的说明文档包括：

- `README.md`：说明目录结构、分类逻辑和查找方式。
- `文件清单.md`：记录文件的原相对路径、新相对路径、类型、大小和状态。
- `待确认清单.md`：记录无法判断的文件和最终决定。
- `命名映射表.md`：展示全部原名与建议新名。
- `重复与版本检查.md`：记录哈希重复、相似名称和版本判断。
- `整理日志.md`：追加每轮盘点、确认和执行记录。

## 七、复盘

这次练习让我最明确的一点是：把本地任务交给 Codex 时，先控制权限和操作顺序，比一开始就追求“整理得漂亮”更重要。

只读盘点、哈希核对和待确认清单解决了三个常见风险：名称相似不等于内容重复，修改时间不等于版本依据，无法判断的文件不应该被强行分类。让 Codex 先展示计划和改名映射，再由人确认，是我会继续保留的安全规则。

下一步若继续执行，我会先确认待确认事项，再批准创建目录和移动清单；执行后补齐索引与日志，并另行规划一次小范围二次调整。
