本次按 Skill v1.1.0 的**路线 B（双站浏览器链接导入）**执行，未运行本地 CLI（`sync_getnote.py` / `getnote.exe` 均未执行）：

2. **本地清单**：把首篇已发布正文的安全字段（序号、标题、文章 ID、规范 URL、状态）写入本机 `browser-state.json` 状态文件，初始状态 `pending`；清单只留在本机，不提交 GitHub。
3. **预检**：对规范 URL 做去重与格式核验；同时用无登录态方式抓取该 URL 做可见性探测（结果见第 7 节，这里先按流程继续）。
4. **得到大脑提交**：在得到大脑网页端（已登录我自己的账号）打开「添加链接 / AI 智能分析」入口，填入该规范 URL，点击「生成笔记」，只提交这一次。
5. **状态核验**：不等"命令跑完了"，而是按 30s / 90s / 150s 间隔对页面做可访问性快照，检查是否出现生成中状态、成功笔记或失败提示，并核对本机状态文件。

## 7. 我遇到的真实阻塞及处理方式

**阻塞：得到大脑网页端「添加链接 / AI 智能分析」对这门课程的正文链接稳定报「笔记生成失败，请重试」，两次独立提交均复现。**

取证与根因判断：
- 用**无登录态**方式抓取该文章规范 URL，返回的只是得到 App 外壳页面（导航文案），**不含任何正文**。该站正文为 JS 渲染且受登录 / 会员墙保护。
- 得到大脑服务端提取时没有我的得到登录态，抓不到正文，生成随即失败。这与官方文档的边界一致：「链接 AI 速记」与「得到笔记导入」是两个独立能力，通用链接提取并未承诺支持需登录的付费页面。
- 结论：这属于"链接导入对受登录保护的付费正文不可用"的**平台级限制**，不是我的操作、会员或额度问题（全程无任何额度 / 权限告警）。

处理方式：
- 本机状态文件中该文章状态从 `pending` 更新为 `failed`，记录错误类别与可追溯证据（失败文案原文、三次快照时间点、未落库核验结果）。
- 按技能规范停止重试，不在无新依据的情况下反复提交。

## 8. 我理解的"Skill 串联"

Skill 串联不是把几条提示词排个队，而是让**每一步的输出成为下一步可检查的输入**：浏览器只负责"发现"自己有权访问的规范 URL；本地清单负责去重和预检，把"哪些可以安全提交"变成一个明确的数字；得到大脑只接收 URL 并自行提取，重复内容不落库；最后用异步状态核验——而不是"命令退出码为 0"——来判定成功与否。任何一步产出不可检查（比如本次服务端提取只返回外壳页），整条链就该停在那一步并如实记录，而不是带着假成功往下走。

## 9. 下次可复用的一条规则

> **链接导入前先做"无登录态可见性探测"**：用一次无凭据抓取检查目标 URL 是否对服务端可见正文；若只返回外壳 / 登录墙，链接导入必然失败，应直接改用平台方提供的官方导入通道（如得到自家的"得到笔记导入"），把失败消灭在预检阶段，而不是消耗一次真实提交去发现它。
