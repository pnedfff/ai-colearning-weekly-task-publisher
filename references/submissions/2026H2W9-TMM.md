本次在用户确认后把执行范围收窄为课程中的 1 篇文章，用它完成“清单 → 预检 → 得到大脑 → 异步核验”的最小可验证闭环。课程完整链接清单和正文均未公开。

## 2. 我的工作流

1. 使用已登录的得到浏览器会话确认课程和文章身份，只读取安全字段，不导出 Cookie、请求头、签名或课程正文。
2. 在本地生成单篇 JSON 清单，只保存顺序、标题、文章 ID 和规范 URL。
3. 对清单执行 dry-run，先检查输入内重复，再按文章 ID、来源 URL 和标题检查得到大脑已有内容。
4. 用户确认后，只提交预检判定为未重复的 1 个 URL，由得到大脑自行提取全文。
5. 等待异步任务结束，再读取笔记的标题、类型和来源网址，并只统计正文长度，不把正文复制到本地或公共作业。

## 6. 真实阻塞及处理

尝试盘点整门课程时，原已登录浏览器扩展连接中断；备用浏览器虽然能打开课程页，但没有得到登录态。已经发现的数据仅保留在当前会话中，没有绕过登录、没有导出 Cookie，也没有把不完整清单提交到得到大脑。

随后按用户明确确认，把范围收窄为已知且有权访问的单篇文章，重新执行单篇清单、预检、同步和异步核验，并在报告中明确区分“课程页面总数”和“本次实际处理数”。

## 7. 我理解的 Skill 串联

Skill 串联不是把多个命令连续跑完，而是让每一步都产生可检查的输出，并把它作为下一步的准入条件：

`浏览器确认权限与链接 → 本地清单提供确定输入 → dry-run 决定是否写入 → 得到大脑异步提取 → 最终状态和内容字段核验`

只要上一步的权限、范围或结果不明确，就不进入下一步写入。

## 8. 下次可复用的一条规则

先让上一步产出可检查、可去重、可恢复的输入，再允许下一步产生外部写入；“已提交”和“全文已生成”必须分开核验。
