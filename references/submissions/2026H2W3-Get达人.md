## 2. 我如何准备安全副本和完成脱敏

- 所有数据均为从零生成的模拟数据，不涉及真实业务信息
- 原始文件存放在独立工作目录，修复版文件另存到 `修复版/` 子目录
- 人名使用常见中文姓名（张伟、李娜、王芳），非真实个人信息
- 公司名称、客户信息、联系方式、金额等敏感字段均未出现

## 4. Codex 向我确认的 5 个关键口径是什么

1. **缺失值规则**：参会人数和时长为必填，不可为空；负责人可空但须标记"待分配"
2. **正常范围**：会议时长 15-120 分钟，参会人数 1-30 人
3. **行动项计数规则**：行动项文件为权威来源，会议纪要中的数量须与之一致
4. **完成状态语义**："未完成"仅用于纪要本身状态，行动项用"未开始/进行中/已延期"
5. **跨文件一致性**：所有文件的会议ID必须可追溯，三份核心文件覆盖所有会议

每项包含：检查内容、合格标准、严重程度（必须通过/建议通过/可选）、需人工确认的例外情况。

## 8. 我人工抽查了哪 3 个修复点

1. **MT-0708 参会人数**：原始为空，修复版填入5人（基于供应链团队常设成员数估算）。抽查确认：原值确实为空，修复值有合理依据但需与团队确认。
2. **ACT-002 截止日期**：原始为 2026-07-09（已过期），修复版改为 2026-07-30。抽查确认：原日期确已过期，新日期合理但需负责人李娜确认。
3. **MT-0709 行动项数量**：原始声明7项，实际文件仅2项。抽查确认：行动项文件中确实只有 ACT-029 和 ACT-030 关联到 MT-0709，修复正确。

## 9. 我做的一次人工纠正是什么

在生成周度统计修复版时，AI 初始建议将"进行中"状态合并到"未完成"中。我纠正了这个口径：**"进行中"是积极状态，不应等同于"未完成"**，要求单独增加"进行中行动项"列。最终修复版中三者关系为：

```
行动项总数 = 已完成 + 进行中 + 未完成（含未开始）
```

## 10. 这次我学到的一条数据核查经验

> **"先定标准，再动手改"不是口号——是防止翻车的唯一方法。**

上周我的 W3 作业被判定不合格，核心原因就是没有走"只读扫描 → 确认口径 → 生成清单 → 按清单检查 → 人工确认 → 另存修复版"这个流程，而是直接把会议纪要扔给 AI 做"清洗"。这次严格按照 W3 要求的流程重做一遍，才发现：
- 同一个"未完成"在不同上下文里含义完全不同
- 跨文件交叉验证能发现仅看单文件发现不了的问题
- 修复版 ≠ 最终版，人工抽查是最后一道防线
