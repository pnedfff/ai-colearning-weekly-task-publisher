## 1. 我评估的 3 个候选流程

1. Excel 数据清洗与整理：操作对象和规则可以明确，适合在脱敏副本中演示和核验。
2. 根据清洗后的 Excel 数据制作可视化看板：存在图表选择、布局和表达判断，需要先缩小为单一固定图表才能安全回放。
3. 分析 Excel 数据并结合看板完成产品调研报告：包含分析、判断和写作，不属于路径固定的低风险录制回放任务。

综合比较后，我选择第 1 个流程。第 2、3 个流程需要较多人工判断，不作为本次回放对象。

## 2. 我最终选择的流程

流程名称：**Excel 销量数据安全清洗**。

用途：在不改动原始表的前提下，按明确规则筛除无有效销量的记录、处理重复记录，并把清洗结果和剔除记录分别保存，便于核对和追溯。

## 3. 它为什么适合本次练习

- 有界面：通过 Windows 版 WPS 表格的筛选、查找、重复项、分列等界面完成示范。
- 路径较固定：输入字段和三条清洗规则可以提前写清，操作顺序可以重复。
- 需要重复：类似数据表会反复执行同类筛选和去重。
- 可降风险：使用脱敏测试副本，保留原始表，不直接删除原始记录。
- 可验证：可以用“原始行数 = 清洗结果行数 + 剔除记录行数”检查结果，并为剔除记录保留原因。

这个流程不是无条件自动化。遇到字段缺失、数值格式异常、并列最高销量或列名变化时必须停止，由人确认后再继续。

## 4. 测试环境和安全副本

- 使用脱敏的 Excel 测试副本，不操作唯一原件。
- 录制前关闭可能显示账号、聊天、邮件或隐私信息的窗口。
- 录屏的数据区域使用遮罩保护，不在报告中附带视频、截图或真实表格。
- 原始工作表只读保留；清洗结果和剔除记录写入新建子表。
- 保存、覆盖文件以及从清洗结果中移出记录前，均保留人工确认点。

## 5. Codex 从示范中提炼出的主要步骤

我在 Windows 版 WPS 表格中进行了约 4 分钟的人工示范。根据录屏中可见的工具栏，Codex 识别到筛选、删除重复项、智能分列、查找、重复值检查、合并工作表和再次筛选核对等操作。

由于数据区域被遮罩，Codex 没有把看不见的列名和条件猜成事实，而是等待我补充业务规则。人工校对后，主线确定为：

1. 打开脱敏测试副本，保留原始工作表。
2. 新建“清洗结果”和“剔除记录”子表，并保留原始行号或其他可追溯标识。
3. 检查“月销量”和“子体销量”是否为有效数值。
4. 将这两个字段都没有有效数值的记录移入“剔除记录”，写明原因。
5. 按非空“父 ASIN”分组，每组保留“子体销量”最高的一条，其余移入“剔除记录”。
6. 对剩余记录按“月销量 + 品牌 + 变体数”组合检查重复，每组保留“子体销量”最高的一条，其余移入“剔除记录”。
7. 将保留记录写入“清洗结果”，再次筛选并核对数量。
8. 保存前停下，等待人工确认。

## 6. 我校对或补充了什么

录屏遮罩使 Codex 只能看到功能入口，不能确认具体字段和规则。我人工补充并校正了三条关键规则：

1. 根据“父 ASIN”字段去重，保留子体销量最高的一条。
2. 剔除“月销量”和“子体销量”都没有有效数值的数据。
3. 当“月销量、品牌、变体数”都相同时，保留子体销量最高的一条。

同时补充了可追溯要求：被剔除的数据不能直接丢弃，必须放入单独子表并记录剔除原因。

## 7. 第一次单条回放的结果

Windows 版 Codex 当前没有显示 `Record and Replay` 按钮，因此没有进行自动回放，也没有声称回放成功。为避免安装来源不明的插件或绕过系统限制，我采用了任务允许的基础完成方式：人工录屏示范、Codex 提炼步骤、人工校对规则，并整理可复用 SOP 和风险清单。

## 8. 我做的一次人工检查或纠正

Codex 首次只能从录屏识别到筛选、重复项、分列等功能，无法判断具体列和保留条件。我检查后发现，仅凭工具栏会把“看见功能”误当成“理解规则”，因此补充了父 ASIN、月销量、品牌、变体数和子体销量之间的准确关系，并要求所有剔除记录保存在独立子表中。

这次纠正让我认识到：录制只能提供操作轨迹，不能替代业务规则和人工验收。

## 9. 可复用 SOP

### 适用场景

- 表头包含父 ASIN、月销量、子体销量、品牌和变体数。
- 数据已经脱敏，并在测试副本中操作。
- 清洗规则与本报告一致，且需要保留完整审计记录。

### 不适用场景

- 字段名称或含义不确定。
- 数据含密码、客户资料、订单号或其他敏感信息。
- 需要直接覆盖唯一原件，或要求不可恢复地删除记录。
- 出现并列最高子体销量，但尚未指定并列处理规则。

### 所需输入

- 一份脱敏 Excel 测试副本。
- 明确的字段名称和数值格式。
- 两个输出子表：“清洗结果”和“剔除记录”。

### 操作步骤

1. 读取表头并确认五个必需字段存在，不一致时停止。
2. 为数据增加原始行号或可追溯标识。
3. 复制数据到工作区域，不修改原始工作表。
4. 检查月销量和子体销量的数值格式；无法判断的值先标记异常，不擅自按零处理。
5. 找出月销量和子体销量均无有效数值的记录，复制到“剔除记录”，填写原因后再从“清洗结果”中移出。
6. 对非空父 ASIN 分组，保留子体销量最高的一条；其他记录复制到“剔除记录”并写明原因。
7. 对剩余记录按月销量、品牌和变体数组合分组，保留子体销量最高的一条；其他记录复制到“剔除记录”并写明原因。
8. 对并列最高、父 ASIN 为空、数值格式异常或规则冲突的记录停止自动处理，交由人工确认。
9. 检查清洗结果中是否仍存在违反三条规则的记录。
10. 核对“原始行数 = 清洗结果行数 + 剔除记录行数”；保存前等待人工确认。

### 禁止事项和人工确认点

- 禁止覆盖原始工作表或唯一原文件。
- 禁止把空父 ASIN 当成同一个父体批量去重。
- 禁止把无法解析的销量值擅自当成 0。
- 并列最高子体销量、列名变化、规则冲突和保存覆盖必须人工确认。
- 被剔除的记录必须先复制到“剔除记录”并标记原因，不能直接丢弃。

### 异常停止条件

- 缺少必需字段或列名不一致。
- 月销量、子体销量或变体数包含无法解释的格式。
- 最高子体销量并列且没有明确的保留规则。
- 行数核对不相等，或出现记录既不在清洗结果也不在剔除记录中。
- 软件弹出保存覆盖、权限或异常提示。

### 验收方法

- 原始表保持不变。
- 每个非空父 ASIN 最多保留一条，且是已确认的最高子体销量记录。
- 月销量和子体销量都无有效数值的记录全部进入剔除表。
- 月销量、品牌、变体数相同的组合只保留最高子体销量记录。
- 每条剔除记录都能追溯原始行号和剔除原因。
- 原始行数等于两个结果子表的记录数之和。
