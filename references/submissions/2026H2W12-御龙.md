## 2. Skill 名称、结构与关键规则

**名称**：`customer-dossier`（客户档案整理）

**结构**（单文件 `SKILL.md`）：
`YAML 头（name/description）` → `用途` → `触发场景` → `不适用场景` → `输入（四类 + 缺失处理）` → `执行步骤（6 步）` → `三份输出结构` → `来源粒度要求` → `冲突处理规则` → `安全边界` → `AI自查 vs 人工核验` → `通用性要求` → `自检清单`

**三条关键规则摘要**：

1. **来源到位置**：金额、日期、账号数、签约状态、承诺等关键结论，必须标注"文件名 + 具体条款号 / 记录日期 / 表格字段"。
2. **冲突并列不裁定**：同一事项多方不一致时并列原值与来源，标注"待人工确认"；不凭来源类型、数量或日期新旧自动选胜者；工作日/自然日口径不混同。
3. **未知不编造**：原文未提及写"原文未说明"；未说明 ≠ 已完成，也 ≠ 确定未发生；需求在合同变更完成前不等于已生效条款。

## 5. 初次发现的问题及上一客户残留检查结果

**初次自查发现的问题**：
- 核验记录中的"上一客户残留检查表"原本直接写出了上一客户的具体名称、编号、金额等值。虽用途是检查，但这些值本身构成信息混入，违反"不残留其他客户信息"的约束。
- **修正**：把该表改为"对照项"表述（如"上一客户名称""上一客户金额"），具体值不落盘，仅人工核验时口头比对。

**残留检查结果**（对三份成果逐项扫描）：
