## 数据与安全副本

我使用一份自制脱敏销售订单测试副本：共 8 条记录、9 个字段，并附字段说明。数据不来自真实客户或真实业务；原始 CSV 全程保留不动，候选结果另存为修复版。检查确认没有姓名、联系方式、账号、客户资料、密钥或本机绝对路径。

## 只读扫描与 5 个关键口径

只读扫描发现 7 个待核实问题：金额单位或计算不一致、状态写法不统一、取消订单仍有金额、满意度超范围、金额缺失，以及一条可能的免费例外。

1. 状态统一为：已完成、处理中、已取消。
2. 金额单位统一为元；已完成或处理中订单金额等于数量乘单价。
3. 正常收费订单数量必须为正整数；数量和金额同时为 0 时保留为待确认例外。
4. 满意度为 1—5 的整数；已完成订单应填写。
5. 已取消订单金额必须为 0。

## 检查、修复与人工复核

我生成了自检清单和问题清单，检查订单号唯一、日期格式、数量、金额、状态、满意度和敏感信息。6 个已确认问题进入候选修复版；数量为 0 且金额为 0 的记录因可能是免费例外而保留原值，等待人工确认。

生成文件包括：候选修复版、检查日志、修复对照清单和口径确认记录。候选修复版有 8 条记录，源文件仍然存在，修复版是独立文件。

我人工抽查了 3 个修复点：金额单位异常已恢复为正确金额；已取消订单金额已归零；一条已完成订单的金额和满意度已分别恢复为正确值和 5 分。对数量为 0 的记录没有凭感觉改成 1，而是保留并标为待确认。

## 经验与脱敏说明

先确认业务口径，再按清单检查；候选修复版必须另存，无法判断的例外要保留原值并留下记录。

本报告只描述数据类型、检查过程和问题类别，不包含原始数据、真实客户资料、联系方式、账号、订单号、本机绝对路径或其他敏感信息。
