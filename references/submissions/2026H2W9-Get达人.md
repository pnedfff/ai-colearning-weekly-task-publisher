## 1. 我处理的是自己有权访问的哪类课程

我处理的是自己已登录得到账号中可访问的一门 Codex 办公实战类课程。课程用于学习如何把 Codex 用到真实办公流程里，本次公开打卡只描述同步流程和核验结果，不公开课程正文和完整链接清单。

## 2. 我的工作流：浏览器 -> 清单 -> 预检 -> 得到大脑 -> 核验

1. 在已登录的得到网页版中打开“我的学习”，确认课程属于自己有权访问的已购内容。
2. 进入课程详情页，读取课程目录，只记录课程名称、讲次标题、规划数量、已发布数量等安全字段。
3. 优先尝试提取整门课程正文链接；发现部分讲次跳转出现重复或错位的文章 ID 后，停止使用整课清单。
4. 收窄范围到本周最相关且已人工验证能打开正文的第 6 讲。
5. 为这一讲生成本地临时清单，先执行 dry-run 查重，不直接写入得到大脑。
6. dry-run 显示没有发现重复后，经人工确认，再把这一条已验证的得到正文 URL 提交给 GetNote。
7. 等待异步任务完成，以最终同步状态和可读笔记核验结果判断是否成功。

## 7. 我遇到的真实阻塞及处理方式

第一个阻塞是 GetNote CLI 在 PowerShell 包装脚本下没有输出授权状态。处理方式是改用已安装目录中的 `getnote.exe` 直接检查，确认账号处于已授权状态。

第二个阻塞是 Windows 默认编码导致同步脚本读取 GetNote 输出时出现解码错误。处理方式是启用 UTF-8 模式后重新运行。

第三个阻塞是当前 GetNote CLI 版本不支持同步脚本里的历史分页参数。处理方式是把 URL 扫描范围限制在最近 1 页，并结合标题查重完成单篇预检。

第四个阻塞是得到网页版课程目录点击时出现部分讲次文章 ID 重复或错位。处理方式是停止整课同步，只同步已经打开并验证标题正确的第 6 讲，避免把错误链接写入得到大脑。

## 8. 我理解的“Skill 串联”是

Skill 串联不是把几个命令连在一起跑完，而是让每一步都产生可检查的输入，再交给下一步：

- 浏览器负责确认访问权限和发现课程目录。
- 清单负责把课程文章变成可去重、可核验的结构化输入。
- dry-run 负责在写入前发现重复和格式问题。
- GetNote 负责根据 URL 提取并保存全文。
- 状态核验负责确认异步任务真的落库，而不是只看命令退出。

一旦上一步结果不可靠，就应该收窄范围或停下来让人判断，而不是继续批量执行。

## 9. 下次可复用的一条规则

先预检，再写入；只同步已经验证标题和 URL 对得上的内容。只要出现重复 ID、标题错位、登录失效或 CLI 参数不兼容，就停止批量流程，保留最小可验证样本继续推进。
